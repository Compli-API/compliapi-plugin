# Screen a counterparty

Screen whatever identifiers the user provides using the CompliAPI MCP tools, then report the compliance picture in one place.

## Workflow

1. Collect every identifier mentioned: wallet addresses (any chain — EVM, Bitcoin, Tron, Solana; ENS names like `name.eth` resolve automatically), email addresses, websites/domains, government-issued IDs, countries, IP addresses, and names of people, companies, vessels or aircraft (note any birth date or country given alongside).
2. Call the matching tool for each, in parallel where possible:
   - `screen_crypto_address` — wallets and ENS names
   - `screen_email` — email addresses
   - `screen_website` — websites, bare domains or full URLs (also checked against two crypto phishing-domain blocklists)
   - `screen_government_id` — passports, national IDs, tax IDs (similarity-ranked matching)
   - `screen_vessel` — ships by IMO number or MMSI; `screen_aircraft` — aircraft by registration (tail number), serial number or Mode S code
   - `screen_name` — a person, company, vessel or aircraft name against sanctions-list names and aliases (OFAC SDN and Consolidated, UN Security Council, EU, UK, Swiss SECO, Canadian, Australian DFAT, New Zealand, French Trésor and Japan MOF, plus the US export-control and debarment lists, which are flagged, never sanctioned); pass `birth_date` (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`) and `country` (name or ISO code) whenever known, `id_number` when the user gives a passport, national ID or registration number for that person or company (a party listing it ranks first), and `type` (`individual`, `entity`, `vessel`, `aircraft`) when it is clear
   - `screen_country` — country names or ISO codes (OFAC sanctions designations, e.g. comprehensive embargoes). To also check the FATF black list (call for action) and grey list (increased monitoring), pass `lists: "ofac,fatf"` — do this when the user asks about FATF, high-risk jurisdictions or AML country risk; FATF is never checked by default
   - `screen_pep` — a person's full name (`name`, 2–200 characters) against the OpenSanctions PEP dataset; pass `birth_date` (`YYYY-MM-DD` or partial, e.g. `1961`) and `country` (name or ISO code) whenever known — they sharpen matching. A PEP check costs 5 requests of quota (one for every other tool), so run it when the user asks about PEPs or due diligence on a person, not by default
   - `inspect_ip` — VPN use, location and a sanctions screen of the IP's country in one call (one request; `vpn` is `null` when unknown, `country_screen` is the country result) — prefer it when both VPN and location matter; `detect_vpn` / `geolocate_ip` give one half each

   Every tool takes an optional `ref` (up to 200 characters): when the user gives their own customer, invoice or wallet id for the subject, pass it — it is echoed in the result and recorded on their audit trail. `screen_name` (1–25, default 10) and `screen_pep` (1–10, default 5) also take `limit`.
3. Interpret each response precisely — the two flags mean different things:
   - `sanctioned: true` — a **government sanctions list** matched (OFAC SDN, OFAC Consolidated, UN Security Council, EU, UK, Switzerland, Canada, Australia, New Zealand, France, Japan, Israel). Treat as a hard stop.
   - `flagged: true` with `sanctioned: false` — a **crime or risk list** matched (e.g. ransomware payment addresses, a crypto phishing website, Tornado Cash association, an address frozen by a stablecoin issuer). Exposure signal, not a designation; say so explicitly.
   - A match on `usdt_frozen` or `usdc_frozen` means the issuer (Tether for USDT, Circle for USDC) has frozen the address at the token contract on the network named in `metadata.network` (for example Ethereum, TRON, Base or Arbitrum). Issuers freeze per network, so one address can return several matches — report each network. Report the `issuer`, `symbol`, `network` and `frozen_at` from `metadata`, and say what it means in practice: the address cannot move that token. The chain does not record why an issuer froze an address, so do not state a reason, and do not call it sanctioned unless a sanctions list also matched.
   - A `screen_website` match on `scamsniffer` or `metamask_phishing` means the site is on a community blocklist of crypto phishing and wallet-drainer websites (ScamSniffer's scam database, MetaMask's phishing list). Say which list named it and that its publisher judged it to be phishing — it is not a sanctions designation. A full URL matches its listed host and is reported as `partial`; subdomains are separate hosts. These lists lag new sites (ScamSniffer's public file runs 7 days behind), so a clean result is not evidence a site is safe — never say it is.
   - A match on `paxos_frozen` means Paxos has frozen the address on Ethereum for the stablecoin named in `metadata.symbol` (PYUSD, USDP or USDG). Paxos freezes per token, so one address can return up to three matches — report each token. Read it like the other issuer freezes: report `issuer`, `symbol` and `frozen_at`, do not state a reason, and do not call it sanctioned unless a sanctions list also matched (many Paxos-frozen addresses are also on sanctions lists, which the same response will show).
   - A `screen_country` match on `fatf` means the country is on a FATF list: `metadata.category` is `call_for_action` (the black list) or `increased_monitoring` (the grey list). FATF does not sanction anyone, so it sets `flagged`, never `sanctioned` — say which FATF list, and that it signals weaknesses in the country's anti-money-laundering regime, not a sanctions designation. If `fatf` is not in `lists_checked`, FATF was not checked; do not say a country is clear of FATF lists.
   - A `screen_name` match on `us_csl` is a US export-control or debarment listing, not an asset-freeze sanction: `metadata.list` names it (Entity List, Denied Persons List, Unverified List, Military End User List, ITAR Debarred or Nonproliferation Sanctions) and `metadata.agency` the US agency. It sets `flagged`, never `sanctioned`. Report the list, the `license_requirement` and `license_policy` when present, and say it restricts US exports and re-exports to that party rather than blocking all dealings; the Unverified List is only a red flag that an end-user could not be checked. These rows have no party type, so do not pass `type` when the user cares about export-control lists.
   - Both false — no match on the lists checked (name the lists from `lists_checked`).
   - `screen_name` matches are fuzzy: each carries a `score` (0–100, `exact` at 100) and `reasons`. A partial match is a lead to review, not a confirmed hit — report the listed `name`, `score`, `party_type`, the published birth dates and countries in `metadata`, and say how they compare with what the user gave. `excluded` counts namesakes dropped because their listed birth dates contradicted `birth_date`.
   - `screen_pep` uses a different envelope: `pep: true` means at least one candidate cleared the 0.7 score threshold (`matches[].match`); lower-scored candidates are listed for review but are not hits. PEP status is a due-diligence signal (current/former public officials, relatives, close associates), **not** a sanctions designation — never report it as `sanctioned`. To sanctions-screen the same person, use `screen_name` (and the other tools on their identifiers).
4. Report per identifier: verdict, which list(s) matched (`matches[].list_name`), match type (exact/partial), and the official `source_url` for every hit so the user can verify against the primary source. For PEP results, report the candidate's `caption`, `score`, `positions`, and `countries`, and the OpenSanctions `source_url`. Never soften or omit a sanctions hit.

## Auth and payment

Tools work with a CompliAPI API token (free tier: 100 requests/month; Developer plan 1,000/month, Team plan 3,000 per seat; every tool call is one request except `screen_pep`, which is 5 — set `COMPLIAPI_API_TOKEN` or `~/.compliapi/token`, see the plugin README) or anonymously via x402 USDC pay-per-call ($0.25 on Base for every tool — `screen_name`, `screen_vessel` and `screen_aircraft` included — except `screen_pep`, which costs $1.25 because its upstream dataset is metered per query — the amount in the payment challenge is always authoritative). If a tool call returns a 402/payment-required error result, tell the user their options: create a free token at https://app.compliapi.com/account/signup, or pay per call with an x402-capable wallet. Do not retry the call unchanged.

## Boundaries

Results are list screenings, not legal advice — for a hit, recommend the user verify via the source URL and follow their compliance program. Identifier screening is typo-exact (government IDs get similarity ranking); `screen_name` and `screen_pep` use scored fuzzy name matching, and `screen_name` covers the OFAC SDN and Consolidated, UN Security Council, EU, UK, Swiss SECO, Canadian, Australian DFAT, New Zealand, French Trésor and Japan MOF lists, plus the US export-control and debarment lists (`us_csl`: flagged, never sanctioned) — do not claim name coverage of other lists. Only screen identifiers the user supplies or that appear in the conversation; never invent identifiers to screen.
